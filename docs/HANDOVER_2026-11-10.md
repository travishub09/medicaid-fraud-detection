## 4b. The three transfers, step by step

### AWS: the server moves to company ownership

**Recommended path: transfer the existing account.** The server, its 1 TB disk, its IP address and every run folder stay exactly where they are. There is no copy, no downtime, no new vCPU quota request (the first one took days) and no change to the ssh lines. It is about 30 minutes of console work done together on a call.

*Trey, in the AWS console of the current account:*
1. Billing and Cost Management → Bills: download the PDF invoices for every month so far (they stay with the account after the transfer).
2. Account → Contact information: replace the name, address and phone with the company's.
3. Billing → Payment preferences: Brad adds the company card on the call and makes it the default; then remove the personal card.
4. Security credentials: change the root user's email to a company address Brad controls (for example `aws@equitableclaims.com`; AWS sends a code to it) and set a new password with Brad on the call. Remove the old MFA device and register Brad's.
5. IAM → Users and Access keys: delete any access key or IAM user that belongs to Trey. Create IAM users (or IAM Identity Center logins) for Brad (admin) and the analyst (EC2 and S3 power user).

*Brad:*
1. Join the call and receive the root login. Store the login and MFA in the company password manager.
2. Optional but recommended: create an AWS Organization from a company management account and invite this account into it, so all company AWS spend is billed in one place.
3. Billing → Budgets: set a monthly budget alert (for example $600) to the owner and Brad.

**Alternative: a brand-new company account.** Use this only if Brad wants a clean account created by the company. Moving the server this way takes about a day.
1. Brad creates the account and requests a vCPU quota of 32 for "Running On-Demand Standard instances" in us-east-2. This can take days, so request it first.
2. Trey creates an AMI of the instance. If the disk is encrypted with the default AWS key, the snapshot must first be copied under a customer-managed KMS key and that key shared with the new account. Trey then shares the AMI with the new account ID.
3. In the new account, the analyst copies the AMI, launches an r6i.4xlarge from it, attaches a security group with SSH only, creates a new key pair, and allocates an Elastic IP.
4. The analyst checks `/data/medicaid` and the code checkout on the new server.
5. Everyone's ssh lines change to the new IP and key.
6. Trey terminates the old instance and deletes the old snapshots only after the analyst confirms a run works on the new server.

### Cloud storage: off the personal OneDrive

Today the server's `rclone` remote `onedrive` pulls the data root from a personal OneDrive (`ops/vm/sync_data.sh`), and the laptop's downloads land in that OneDrive folder. The server's disk is already the working copy, so OneDrive is used only as the inbox for new downloads and as the backup.

**Target: an S3 bucket in the company AWS account.** S3 is the backup and the downloads inbox. The server reaches it through an IAM role, so no storage key is stored on the server. Documents for people stay on the company Drive, as now. Cost is about $23 per TB per month.

*Brad, or the analyst with Brad's AWS login:*
1. S3 → Create bucket: a private bucket in us-east-2, versioning on, public access blocked (name it, for example, `equitable-medicaid-data`).
2. IAM → Roles: create an EC2 role with read and write access to that bucket only, then attach it to the server (EC2 → Instance → Actions → Security → Modify IAM role).

*Analyst, on the server:*
1. Before anything is removed, take a last copy of anything that is only on OneDrive. `copy` never deletes; do not use `sync` here, because files placed on the server directly (CLIA, the rosters) are not in OneDrive.

   ```bash
   rclone copy onedrive:Desktop/data/preclean /data/medicaid/preclean --transfers 8 -P
   ```

2. Add the company remote: `rclone config` → new remote `company`, type `s3`, provider AWS, `env_auth = true`, region us-east-2.
3. Back up the data root, then check the totals match:

   ```bash
   rclone sync /data/medicaid company:equitable-medicaid-data/data --exclude "interim/**" --transfers 16 -P
   rclone size /data/medicaid --exclude "interim/**"
   rclone size company:equitable-medicaid-data/data
   ```

4. Point the sync script at the company remote. `sync_data.sh` reads these two variables, so no code changes:

   ```bash
   echo 'export ONEDRIVE_REMOTE=company' >> ~/.medicaid_env
   echo 'export ONEDRIVE_DATA_PATH=equitable-medicaid-data/data' >> ~/.medicaid_env
   ```

5. Remove the personal connection:

   ```bash
   rclone config delete onedrive
   ```

*Trey:*
1. In the Microsoft account (account.microsoft.com → Privacy → Apps and services), remove rclone's access.
2. Once the Drive uploads are confirmed, the laptop's OneDrive `Desktop\data` folder can be archived and deleted.

*New owner, after the switch:* new browser downloads are uploaded through the S3 console into `data/preclean/<folder>/`, the same save paths the reminders give. Then the analyst runs `bash ops/vm/sync_data.sh down-preclean`.
